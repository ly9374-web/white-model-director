# 体积碰撞约束

所有生成的白模视频必须没有模型穿透。使用工程中的 `white-model/collision.js`（空骨架自带，无需新写），在引入资产、搭建骨架或动画时同步扩展碰撞表示和运动验证，不能退化为中心点距离或二维平面判断。

## 模型覆盖与接触

- 每个实体都有对应的碰撞体。默认以每个实体的可见几何网格构成复合体，使用变换后的三维包围体做 SAT 检测，包含父级旋转、非均匀缩放与切变。这是保守包围体；复杂模型可以改用更精确、仍覆盖实体的凸包、胶囊或三角网格。
- 椅子、桌子、收纳盒和门洞保留空隙，不能把整个空心物体或房间当作一个填实的大盒子。新添加而未列入道具注册表的实体也必须纳入检测。蒙皮与 morph 模型使用变形后的顶点计算体积；实例模型、自定义顶点着色或未支持的变形必须先扩展对应碰撞体，默认无法认证时中止检查。
- 作为同一建筑构件的墙、门框等固定拼接部分组成一个装配体；可动门扇、独立家具和人物是不同实体。隐藏对象、天花板、墙体或编辑器剖切只是观察操作，不移除实体的碰撞；第一人称隐藏头部仍保留头部体积。剧情中真正出现、消失的实体须由世界动画声明生命周期，不能通过导演台隐藏按钮绕过碰撞。
- 人形不同部位之间也检查碰撞。相邻部位仅允许连接关节周围的小范围拼装接缝，不能豁免整条手臂与躯干。改编成人物、动物或机器时，按真实骨架声明部位、连接点及接缝尺寸。
- 脚与地面、身体与椅面、手与道具可以接触，不能把几何体埋进地面、桌子或手臂。抓握关系不能成为整个人物与道具之间的碰撞豁免。
- 默认容差 `COLLISION_EPSILON = 1e-5` 米用于浮点误差；禁止用扩大容差、缩小碰撞体或把实体标成编辑器辅助对象来隐藏穿模。

## 编辑与修正

剧情镜头使用小体积防止进入墙体与道具；安装在主角身体内的虚拟眼位不作为第二个实体与该主角相撞。观察镜头不参与实体碰撞。

导演台采用自由编辑，不在平移、旋转、缩放、关节、手部目标、复制、保存、导入或导出时扫描碰撞或截停。保留坐标、正尺寸与绑定关系有效性校验。`DirectorModel.protectNode` 的检测能力可供专门的生成验证使用，默认导演台传入 `liveCollision:false`。

自由编辑目标和副本可以暂时重叠，用来表达期望；不等于允许正式动画穿模。导入失败保留原工作状态。将包转成原动画时，检查并修正目标姿态及路径的实际穿透，必要时微调接触位置并说明；不能把自由摆放的数据直接当作已验证的动画。

编辑目标不自动重写连续动画。把目标状态转为动画时，应根据人物、道具和门的体积规划路线与动作，按需要延长时长。不得通过瞬移、穿过障碍或只改变镜头隐藏碰撞。

## 生成前检查

`world.checkCollisions()` 返回当前场景的体积重叠；`world.validateCollisions({fps})` 及播放页的 `window.__wm.validateCollisions({fps})` 检查原动画。覆盖首末帧、每个录制帧，并按模型厚度和运动距离增加帧间子步。高速旋转、复杂曲线或外部动画须使用可靠的速度／角速度上界或连续碰撞检测进一步提高子步密度，不能只凭帧端点位移认为路径安全。

录制脚本先写出 `*-碰撞检查.json`。发现重叠则中止编码，报告时间、帧号、涉及对象和穿透深度。修复后重新检查；不提供“忽略碰撞继续导出”的开关。预览关键帧允许用于诊断，不能当作无穿模的成片。

新故事交付前确认碰撞报告为 `ok: true`，再做画面验收和完整视频录制。空骨架本身没有历史碰撞，但搭建过程中产生的摆姿和接触问题必须修正，不能把「骨架默认通过」当作新场景已满足这条要求。

## 验证入口

当前项目中的 `scripts/check_volume_collision.mjs` 覆盖旋转盒、空心复合体、地面接触、自身部位、薄墙穿越和帧间检测；`scripts/check_director_ui.py` 与 `scripts/check_director_recording_cutaway.py` 检查导演台录制流程与碰撞门禁。新工程须按自己的资产、骨架与动作补充同类测试。
